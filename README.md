# openwrt-bypass-kit

Переносимый набор для OpenWrt-роутера: **обход DPI (zapret)** + **точечный сплит-прокси**
(sing-box redirect, только нужные домены идут через ноду, остальное — напрямую) + **чистый DoH**
для проксируемых доменов. Управляется одной командой с компа (Linux / macOS / Windows).

Задумано так, чтобы отдать другому человеку: он вписывает **свои** IP/ноды/домены в текстовые
файлы и запускает установку одной командой поверх свежего OpenWrt.

## Что внутри

```
config/
  kit.conf            ← адрес роутера, порты, что включать (правится под себя)
  nodes.list          ← твои прокси-серверы (vless:// ссылки) — НЕ коммить в git
  domains.list        ← какие домены гнать через ноду
  ru-split.list       ← РФ-зоны/сервисы, что резолвим российским DNS (чинит VTB и пр.)
  telegram-cidr.list  ← сети, что проксируются по IP (Telegram MTProto)
  zapret.conf         ← стратегии обхода DPI (дефолт рабочий)
bin/
  netctl              ← пульт для Linux/macOS
  netctl.cmd          ← пульт для Windows 10/11
router/
  netkit              ← движок; сам ставится на роутер, руками трогать не надо
```

### Что кит делает на роутере

- **zapret** — обход DPI на прямом трафике (YouTube, голос Discord и т.п.).
- **Точечный прокси** (sing-box redirect) — только домены из `domains.list` идут через
  твою ноду, остальное напрямую. Лёгкий, без TUN.
- **Весь DNS через чистый зарубежный DoH** (два резолвера для резервирования) — чтобы
  провайдер не травил/не подменял ответы.
- **Split-DNS для РФ** — зоны из `ru-split.list` резолвятся российским DNS (иначе банки
  типа VTB, прячущие записи от иностранных резолверов, «не открываются совсем»).
- **geoblock-автосписок** — раз в сутки тянет список ушедших-из-РФ сервисов
  (itdoginfo/allow-domains, ~460 доменов) и гонит их через ноду. С валидацией и откатом.
- **Сторож нод** — каждые 3 мин проверяет прокси; если нода упала, форсит пересбор, чтобы
  вернуть интернет, не трогая обычный трафик.
- **Докачка зависимостей** — `install` проверяет каждый пакет (sing-box, dnsmasq-full,
  https-dns-proxy, jq, curl) и доставляет недостающее.

**Как это устроено:** вся логика живёт на роутере (`/usr/sbin/netkit`, POSIX-шелл). С компа
`netctl` просто заливает конфиг по SSH и дёргает `netkit`. Поэтому одинаково работает из-под
Linux, macOS и Windows — нужен только `ssh` (в Windows 10/11 он есть из коробки).

## Предпосылки

1. Роутер на **OpenWrt** (проверялось на 25.12.5, mediatek/filogic), WAN в интернет.
2. На роутер заброшен твой SSH-ключ (`ssh-copy-id root@192.168.1.1`), заходит без пароля.
3. У тебя есть **VLESS-Reality ноды** — как `vless://…` ссылки (даёт любой нормальный провайдер
   через «поделиться»). Без нод работает только zapret; прокси-часть можно выключить
   (`PROXY_ENABLE=0`).

## GUI (графический интерфейс)

Для тех, кто не хочет в терминал — есть оконная оболочка на zenity: мастер установки
(форма с IP роутера, вставка нод, галочки компонентов) и панель управления (статус, чекап,
добавление нод вставкой из буфера, домены, geoblock).

```sh
bin/netgui        # KDE/GNOME; при первом запуске сам создаёт ярлык в меню приложений
```

Ноду можно **вставить прямо из буфера** (Happ часто копирует конфиг текстом): жмёшь «Добавить
ноду», Ctrl+V ссылку `vless://` или JSON — оболочка сама разберёт формат и зальёт на роутер.

В терминале то же самое:
```sh
netctl nodes add-json           # возьмёт JSON из буфера обмена (KDE klipper)
netctl nodes add-json файл      # или из файла
netctl nodes add-url 'vless://…' # или готовой ссылкой
```

## Быстрый старт (терминал)

```sh
# 1. правим под себя
cp config/nodes.list.example config/nodes.list   # nodes.list в .gitignore (личные ноды)
nano config/kit.conf        # ROUTER_IP и т.п.
nano config/nodes.list      # вставляем свои vless:// ссылки
nano config/domains.list    # при желании меняем список (дефолт уже большой)

# 2. ставим всё на роутер (Linux/macOS)
./bin/netctl install
#    Windows:  bin\netctl.cmd install

# 3. проверяем
./bin/netctl status
./bin/netctl doctor
```

`install` на чистом роутере сам: поставит пакеты (`sing-box`, `dnsmasq-full`,
`https-dns-proxy`, `jq`, `curl`), скачает и развернёт zapret, сгенерит все конфиги, поднимет и
включит в автозапуск сервисы.

## Повседневные команды

```sh
netctl domains list                    # что проксируется
netctl domains add depop.com ebay.com  # добавить (сразу применяется)
netctl domains rm  netflix.com         # убрать

netctl nodes list          # ноды и какая активна
netctl nodes test          # прогнать все ноды: живость + выходной IP/гео
netctl nodes use 2         # закрепить ноду №2 основной

netctl zapret on|off|check # check = blockcheck (подбор стратегии под провайдера)
netctl proxy  on|off       # прокси-часть отдельно от zapret

netctl geoblock update     # обновить список ушедших-из-РФ сервисов сейчас
netctl geoblock count      # сколько доменов в geoblock-списке
netctl geoblock on|off     # включить/выключить авто-список

netctl status              # состояние
netctl doctor [домен]      # глубокий чекап: DNS→набор→выходной IP→гео→QUIC→РФ-split→кроны
netctl logs sing-box|zapret|dns

netctl apply               # залить локальные правки config/* и перезапустить
netctl pull                # забрать текущий конфиг с роутера в config/ (для git/бэкапа)
```

## Как добавить новый сервис

Просто `netctl domains add <домен>` — движок сам добавит его в наборы `proxy4/proxy6` и на
чистый DoH-резолв. Если у сервиса своя CDN на других доменах и часть контента не грузится —
добавь и их (`netctl domains add foousercontent.com foocdn.net`).

**YouTube намеренно не в списке** — им занимается zapret напрямую, гнать видео через ноду только
замедлит.

## Обновление нод (когда провайдер прокси выдал новые)

Полностью автоматически тянуть свежие ноды из Happ **нельзя** — подписка привязана к HWID,
а её база и рантайм-конфиг движка зашифрованы (проверено: ни база, ни память xray, ни повтор
запроса подписки надёжного результата не дают). Поэтому надёжный путь — полу-ручной, зато
занимает секунды и нужен редко (IP нод меняются нечасто):

- Happ **дал ссылку** `vless://…` → `netctl nodes add-url 'vless://…'`
- Happ **дал JSON-файл** (частый случай — экспорт конфига) → `netctl nodes add-json путь/к/файлу`
  (конвертер `tools/xray-json-to-vless.sh` вытащит из xray-JSON все ноды с параметрами)

Оба варианта дописывают в `nodes.list` (с дедупом) и применяют на роутер.

**Когда обновлять — подскажет монитор** `tools/happ-live-nodes.sh` (запускать на машине с Happ):
он показывает, к каким нодам Happ подключён сейчас, и есть ли они на роутере. Если появилась
нода, которой у роутера нет — пора добавить её ссылкой (шаги выше).

```sh
sh tools/happ-live-nodes.sh    # спросит sudo-пароль один раз (читает соединения xray от root)
```

Ноды на роутере и так перебираются автоматически (urltest failover + `proxy-watchdog`), так что
обновление вручную нужно только когда провайдер прокси реально сменил сервера.

## Если РФ-сайт «не открывается совсем»

Скорее всего он прячет DNS-записи от зарубежных резолверов (так делают банки — VTB, Сбер-онлайн).
Добавь его домен/зону в `config/ru-split.list` и `netctl apply` — он станет резолвиться российским
DNS. Зоны `.ru`, `.su`, `.рф` уже там, так что большинство РФ-сайтов покрыто из коробки; вручную
дописывают только РФ-сервисы на не-`.ru` доменах.

## Чекап (`netctl doctor`)

Показывает по шагам: работают ли сервисы → резолвится ли тест-домен через DoH → попал ли его IP
в набор `proxy4` → какой реальный выходной IP и страна через активную ноду → режется ли QUIC.
Если что-то красное — сразу видно, на каком звене отвал.

## Тонкости и грабли

- **Тестировать только с клиента роутера** (`curl --interface <wifi>`), не с самого роутера:
  трафик самого роутера в prerouting-редирект не попадает. И выключай на тест-устройстве
  сторонний VPN/TUN — он перехватит трафик до роутера.
- **dnsmasq-full**: обычный dnsmasq на OpenWrt собран без `nftset`. `install` сам меняет его на
  full; на время замены DNS роутера ненадолго переключается на `1.1.1.1`.
- **zapret на чужом провайдере** может потребовать другую стратегию — подбирай через
  `netctl zapret check` (это `blockcheck.sh`, он сначала глушит zapret, чтобы не мешал замеру).
  Рабочую строку впиши в `config/zapret.conf` и `netctl apply`.
- **Telegram по IP**, а не по домену (MTProto стучится в IP мимо DNS) — держи актуальные сети в
  `config/telegram-cidr.list`, официальный список: `https://core.telegram.org/resources/cidr.txt`.
- **Некоторые сайты за Cloudflare** (напр. Depop) отдают `403` голому `curl` без браузерных
  заголовков — из настоящего браузера всё открывается, это не поломка прокси.
- **TUN sing-box не используется намеренно** — на слабом железе (MT7981/256МБ) он вешал роутер.
  Здесь только лёгкий `redirect`-инбаунд, нагрузка копеечная.

## Откат

```sh
netctl proxy off      # выключить прокси-часть (zapret остаётся)
netctl zapret off     # выключить zapret
```
Бэкапы `/opt/zapret/config` кладутся рядом с меткой времени при каждом `apply`.
